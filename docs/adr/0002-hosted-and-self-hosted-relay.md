# ADR-0002：默认共享托管，同时支持开源自建

日期：2026-10-09；更新：2026-10-10。状态：已确认；受控托管与独立自建部署的核心流程已验证，公开默认服务和开源发布尚未完成，见[候选记录](../validation/2026-10-10-candidates.md)。

## 背景

既有设计以可信个人设备访问指定 Herdr 实例为授权场景，但未确定 Relay 是个人独占、自部署分发还是共享服务。不同选择会影响首次使用、资源隔离和部署交付。

## 决策及依据

本轮需求访谈 Q1，用户明确回答：“默认共享托管，支持用户自建，都是开源的”。

据此确定：

1. 默认提供共享托管 Relay，用户可通过它访问自己获准使用的 Herdr。
2. 支持用户自行部署并使用 Relay。
3. 项目全部开源，包括端点、云端中继与插件；具体许可证另行确认。

后续 [ADR-0004](0004-cli-and-cloudflare-first-release.md) 将第一版限定为 CLI 与 Cloudflare Relay，插件的开源交付随其后续版本进行。

## 影响

- 用户使用默认服务时无需先部署自己的 Cloudflare 资源。
- 需要保护不同用户的设备、共享目标和通道之间的隔离。
- 需要端点选择自建服务的方式，以及可复现的部署说明。
- 默认托管与自建都要覆盖原生连接、配对、加密和撤销等核心流程。
- 既有“可信个人设备”的描述用于界定实例授权，不再意味着整个 Relay 只服务一个人。
- 公共服务的准入、限流、资源与费用策略需要在发布前明确。

## 保留的既有约束

两端 Rust、云端 TypeScript Worker/DO、Herdr 专用、端到端加密以及 MCP 不进入链路的方向保持适用。支持自建本身不决定引入 VPS 等其他后端。

## 尚未决定

生产服务运营方、预算与正式配额、开源许可证和发布渠道仍待[发布决定](../release-readiness.md)。设备签名准入已有实现；自建安装、服务切换和重新配对规则已记录于[自建说明](../self-hosting.md)。

账号问题已在后续 [ADR-0003](0003-accountless-device-pairing.md) 中确定为免注册设备配对。

默认服务在后续 [ADR-0009](0009-public-free-relay-with-quotas.md) 中确定为公开免费，并设资源配额。
