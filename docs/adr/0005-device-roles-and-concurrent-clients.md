# ADR-0005：设备角色对称，支持多实例与多客户端

日期：2026-10-09。状态：**部分被 [ADR-0012](0012-single-active-client-per-target.md) 取代（2026-10-10）**。以下保留当时的决定与依据；同实例多客户端并发已撤回。设备双向角色、多实例发布和多设备授权仍有效，当前同实例只允许一个活动 Relay 客户端。

## 背景

原设计建议首版限制一个活动远程客户端，早期图示将两台电脑分别标为主机和客户端。用户明确了设备可承担双向角色，以及同一实例被多台设备同时访问的需求。

## 决策及依据

用户对 Q5 回答：“两边是双向的，一个 cli 可以作为 客户端也可以是 server，一个实例可以分享给多个主机”。对 Q6 选择：“允许多个远程客户端同时连接和操作”。

后续 Q7 补充选择：“需要：可同时共享多个实例，连接时选择设备和实例”。

据此确定：

1. 同一个 Rust CLI 支持共享本机实例和连接远端实例两种能力，设备不固定为某一种角色。
2. 一个共享 Herdr 实例可授权多台设备访问。
3. 第一版支持多个已授权远程客户端同时连接并操作同一实例，取消单活动客户端限制。
4. 同一设备可以同时发布多个不同 Herdr 实例，客户端选择设备和实例来连接。

## 影响

- host/server 与 client 是相对于某个目标和连接的角色；CLI 的 server 角色不同于云端 Relay。
- Relay 房间和端点需要管理同一目标下多个客户端通道，不能只有一个可被新连接覆盖的客户端槽位。
- 客户端身份、授权、连接标识、代次和待发送数据需要按相应通道区分，并限制目标及设备总资源。
- 撤销、断开或替换某个客户端连接时，应只影响指定范围，不能误关其他有效连接。
- 需要按实例管理共享目标与连接；停止一个实例的共享，不能误停同设备上的其他共享目标。
- 需要验证 Herdr 原生多客户端的输入、显示与 resize 行为；具体 IPC 和网络复用方案尚未选择。
- 既有端到端加密、主机授权、无输入重放和目标变更规则继续适用。

## 尚未决定

- 同时发布与连接采用怎样的进程和命令运行方式。
- 设备实例数和每实例并发上限、同一设备多次连接，以及原生视图和输入竞争的行为。

Q8/Q9 的后续 [ADR-0006](0006-directional-device-wide-authorization.md) 已确定按设备授权全部已共享实例，两个方向分别授予。
