# ADR-0008：持久共享 session，并自动重新连接

日期：2026-10-09；更新：2026-10-10。状态：已确认；网络、session 和 daemon 重启恢复已有实现与[四平台候选记录](../validation/2026-10-10-candidates.md)，完整平台/终端故障组合验收仍未完成。

## 背景

原设计建议 Herdr 运行实例更换后重新确认共享。用户选择无人值守恢复，同时要求网络恢复时重新 attach，不缓存或重放输入。

## 决策及依据

Q12 用户选择：“自动恢复该 session 的共享，沿用现有设备授权”。问题已明确 CLI 不负责启动 Herdr。

Q13 用户选择：“自动重连，建立新通道并重新 attach；断线期间不缓存或重放输入”。

1. 发布配置绑定本机用户明确选定的逻辑 session，不局限于某次 Herdr 进程运行。
2. 同一已配置 session 重启后自动恢复共享，沿用有效设备授权，无需本机重新确认。
3. 网络中断后客户端自动建立新通道并重新 attach，用户可取消等待。
4. CLI 只接入已经运行的 Herdr，不自动启动 Herdr，也不回退到其他 session。

## 影响

- Herdr 进程、网络通道与逻辑共享目标的生命周期分别管理。
- Herdr 退出后旧通道失效；恢复时使用新通道与新的连接代次，不继承旧通道中待执行的数据。
- 断线期间不缓存输入，不重放执行结果未知的按键。
- 显式停止共享的目标保持停用，自动恢复不能绕过停用或设备撤销。
- 未配置的其他 session 不自动发布，也不用于连接失败时的回退。
- 此决定替换原设计中“每次目标 Herdr 重启都使旧授权失效并需要重新确认共享”的建议。

完整需求与访谈记录见 [REQUIREMENTS.md](../../REQUIREMENTS.md)。

网络恢复实现与验证见[协议](../../protocol/access-v1.md)及[验收记录](../validation/2026-10-10-reconnect.md)。每次重试先释放旧通道，再创建新通道与完整 TLS 握手；有上限且带抖动的退避遵守 Retry-After，离线输入持续丢弃。目标忙碌、授权、身份和版本错误终止恢复。

已保存目标的 socket 变化通过本地定期检查发现。旧运行代次停止接纳连接并取消、等待其 native/TLS 操作结束，再提供新代次；其他目标不替换。正常 Herdr shutdown 导致的客户端非零退出会重新查询授权目标的运行状态，不能一律视作客户端损坏或一律重试。实现边界与状态观测限制见[运行恢复验收](../validation/2026-10-10-runtime-recovery.md)。
