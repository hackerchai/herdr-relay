# Interactive CLI release acceptance — 2026-10-10

Scope: issues #33–#39. macOS arm64 and Ubuntu 26.04.1 arm64 in OrbStack;
official Herdr 0.9.3; production Relay at https://herdr-relay.hackerchai.com.
No permanent e2e suite was introduced.

## Interactive workflow

- Fresh XDG state roots exercised default profiles without `--profile`.
- `serve` selected two named sessions on each OS and automatically installed and
  started the unattended user service. Exiting setup left it running.
- One-use pairing links worked by bracketed copy/paste in both directions.
  A legacy `hrp1:` invitation worked; an expired link was rejected without a grant.
- Two real host profiles with the same hostname paired into one client. The
  second received `herdr-relay-demo (2)` and exposed only its own selected
  session; the original active connection continued normally. Its temporary
  service was stopped and uninstalled after verification.
- Bare invocation and `connect` opened the named host/session browser. Alias
  `Ubuntu QA` persisted. Native Unicode commands reached both remote computers.
- Repeated detach/reattach succeeded, preserving the native session. A second
  browser displayed `busy` and refused access without affecting the first client.
- Help, filter/navigation, resize, back, and cancellation were inspected. SIGINT
  and SIGHUP restored terminal flags; Ctrl-C also cancelled asynchronous loading.
  A non-TTY invocation returned an actionable error instead of hanging.
- Login autostart was toggled off/on on both platforms. Linux boot mode preserved
  the already-enabled linger policy. Definitions use the unattended daemon command.
- A failing pending service executable on both platforms produced
  `UPDATE_ACTIVATION` and restored/restarted the prior working binary/definition.

## Platform startup coverage

macOS: LaunchAgent settings and launchd lifecycle were inspected and exercised.
Actual GUI logout/relogin and a physical reboot were not performed.
Linux: systemd user enablement, start/stop/restart and effective linger state were
exercised. An actual logout cycle and VM reboot were not performed in this run.
Neither platform's result is presented as actual reboot acceptance.

## Real CLI and service upgrades

The starting CLI and copied service executables were the published v0.2.0 builds.
Their archive digests matched the official GitHub Release assets. Both update
processes had GitHub environment credentials removed and no gh executable on PATH;
the one-time `--repository` argument selected the new public channel from v0.2.0.
The installed v0.2.1 uses that channel by default.

- On each OS, SIGINT at the download stage exited unsuccessfully and left the
  installed executable's SHA-256 unchanged. A later retry succeeded.
- macOS: v0.2.0 → v0.2.1 updated both copies while preserving the stopped service.
- Ubuntu: an existing native client remained connected while the CLI updated.
  The service stayed on v0.2.0 with the same pre-update start timestamp and reported
  a pending update. The original terminal wrote `ACTIVE_UPDATE_SURVIVED` afterwards.
  After detach, service stop/start applied v0.2.1 and cleared the pending update.
- Verified installers updated the global `~/.local/bin/herdr-relay` on both OSes.
  Running update with the original demo profiles then detected their older v0.1.1
  service copies despite the CLI already being v0.2.1. Both services upgraded and
  restarted successfully; repeated update reported already up to date.
- All 24 pre/post hashes matched across both original demo and acceptance profiles:
  identity keys/certificates, pairing grants, shared targets, host aliases, service
  configuration where present, and the official Herdr executable. No re-pairing
  was needed. Original default user profiles were not used for these tests.
- Both newly installed CLIs selected named hosts/sessions and attached again.
  Remote commands wrote `POST_RELEASE_0.2.1_FROM_MAC_OK` on Ubuntu and
  `POST_RELEASE_0.2.1_FROM_VM_OK` on macOS. Detach restored the session picker.

The prior forced activation-failure checks on both platforms restored the working
service binary and definition; checksum/archive rejection remains covered by the
focused Rust tests. These are separate observations from the successful real
release download/upgrade tests above.

## Handoff and cleanup

Both global CLI installations and both original demo service copies are v0.2.1;
the original demo services remain online. Their existing autostart preferences
were retained. Temporary acceptance services were uninstalled after preservation
checks, and only the four test Herdr sessions were stopped. Private acceptance
records and previous executable backups remain available locally. Normal fresh
setup is `herdr-relay serve`, then `herdr-relay pair`, then bare `herdr-relay`.
No profile or internal ID is required for that workflow.
