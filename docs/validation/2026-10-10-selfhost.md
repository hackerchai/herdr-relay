# Fresh Cloudflare self-host acceptance — 2026-10-10

Issue: [#15](https://github.com/hackerchai/herdr-relay/issues/15).
A new `herdr-relay-selfhost-check` Worker was deployed using the documented
config generator and pinned Wrangler 4.149.0. Its first deployed version was
`59f5d208-1314-457f-a659-46ac629f7338`, at
`https://herdr-relay-selfhost-check.hackerchai.workers.dev`. It has its own three
SQLite Durable Object namespaces and v1/v2 migrations. Two newly initialized
local profiles had no grants or prior state. A two-device test allowlist kept
this acceptance deployment isolated while global public admission work proceeds.

Both endpoints used the actual HTTPS origin and ordinary public certificate
validation. No transport override, skipped TLS check, default hosted account or
shared application bearer credential was used. Cloudflare deployment credentials
stayed in the operator's environment, not the Worker vars or endpoint profiles.

The publisher explicitly shared an existing isolated Ops native Herdr instance.
Fresh pairing succeeded through the new deployment; encrypted discovery listed
that target, and the native client typed a marker confirmed by the server's pane
read. A second signed attach received `409 TARGET_BUSY`; subsequent input through
the original client still worked. Configurable quotas cannot change Room's
single-instance exclusion rule.

Revoking the connector ended its active native client with status 1 in 2.07
seconds (including the CLI operation and polling). PTY termios was restored.
Subsequent discovery returned `NOT_AUTHORIZED`; the native Herdr workspace
remained running. This is one functional timing sample, not a latency SLO.

The same controlled run checked diagnostics without printing secret material:

- A deliberately forged signature on a fresh proof returned `401 ACCESS_INVALID`.
- A version-2 challenge returned `400 INCOMPATIBLE_PROTOCOL`.
- A separate local workerd with the ROOMS binding removed returned
  `503 RELAY_UNCONFIGURED`, not an exception body.
- A client selecting another origin returned `PROFILE_MISMATCH`.
- Attempting `relay switch` while the publisher was active returned `SERVICE_BUSY`.

Quota enforcement had already been exercised against a separately lowered local
configuration in [flow-control acceptance](2026-10-10-flow-control.md); the same
limits module is used here. The deployment guide describes quota bounds,
Retry-After, migration/binding preservation, operator credentials, explicit origin
switching and recovery without reviving stale grants. A focused Rust test checks
atomic origin reset, lock exclusion, old receipt/invitation rejection, stable
identity/target storage and monotonic grant versions. No e2e suite was added.

The real origin-switch round trip then passed. With the publisher stopped, both
profiles switched to a distinct origin and back. Their device key/certificate
and shared-target file hashes were unchanged; incoming/outgoing grants were
empty. After restarting the publisher, an invitation captured before switching
returned `PAIR_INVALID`. Fresh pairing issued grant 3, the original target was
still discoverable, and a native client operated it and detached with status 0
and restored termios. The existing unit suite now has 37 Rust tests.
