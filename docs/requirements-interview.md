# Herdr Relay 需求访谈记录

初次访谈：2026-10-09；后续修正：2026-10-10。当前需求以 [REQUIREMENTS.md](../REQUIREMENTS.md) 为准；本文件保留问题、用户回答和对应决定。

### Q1：首版 Relay 的部署和使用范围

状态：已确认。

用户原话：“默认共享托管，支持用户自建，都是开源的”。

记录为 [ADR-0002](adr/0002-hosted-and-self-hosted-relay.md)。不再把个人独占 Relay 当作首版前提；“可信个人设备”仍可描述每个用户对自己 Herdr 的授权边界。

### Q2：默认共享 Relay 是否要求注册或登录账号

状态：已确认。

用户选择：“免注册：通过设备身份和配对使用，在自己的主机上管理授权设备”。见 [ADR-0003](adr/0003-accountless-device-pairing.md)。

### Q3：首个可发布版本的交付程度

状态：已确认。

用户原话：“可用 cli 和 cloudflare 远端 relay 这是第一个版本的”。确定首版为 CLI 与 Cloudflare Relay，插件后续；见 [ADR-0004](adr/0004-cli-and-cloudflare-first-release.md)。

### Q4：首版系统与架构支持

状态：已确认。

用户选择：“两端支持 macOS（Apple Silicon、Intel）和 Linux（x86_64、arm64）”。最低系统版本、Linux 发行版和终端范围继续待定；Windows 不在本次确认的首版平台中。

### Q5：每个主机端同时共享的实例数量

状态：已确认角色模型；独立实例数量由 Q7 补充确认。

用户原话：“两边是双向的，一个 cli 可以作为 客户端也可以是 server，一个实例可以分享给多个主机”。据此明确设备可承担任一角色，同一实例可分享给多台设备；不据此推定一台设备只能发布一个实例。

### Q6：一个共享实例的远程客户端并发规则

状态：历史回答；同实例多人并发已被 Q16（2026-10-10）取代。

用户选择：“允许多个远程客户端同时连接和操作”。原先的单活动客户端建议取消，见 [ADR-0005](adr/0005-device-roles-and-concurrent-clients.md)。主机本地 Herdr client 的行为需单独验证。

### Q7：一台设备能否同时共享多个不同的 Herdr 实例

状态：已确认。

用户选择：“需要：可同时共享多个实例，连接时选择设备和实例”。已同步到 [ADR-0005](adr/0005-device-roles-and-concurrent-clients.md)。

### Q8：配对后的实例访问范围

状态：已确认。

用户选择：“按设备授权：可访问对方所有已共享实例，包括以后新增的共享实例”。

### Q9：配对与访问授权的方向

状态：已确认。

用户选择：“分别授权：A 允许 B 访问后，B 若要分享给 A，需要单独授权”。Q8/Q9 见 [ADR-0006](adr/0006-directional-device-wide-authorization.md)。

### Q10：首次配对是否需要发布方再次确认

状态：已确认。

用户选择：“A 生成一次性配对串；B 导入即获得授权，无需 A 再次确认”。见 [ADR-0007](adr/0007-single-use-pairing-grant.md)。

### Q11：本机发布程序的运行方式

状态：已确认。

用户选择：“支持安装为后台用户服务，提供启动、停止和状态命令；另保留前台运行方式”。已补充到 [ADR-0004](adr/0004-cli-and-cloudflare-first-release.md)。

### Q12：已共享 Herdr session 重启后的恢复

状态：已确认。

用户选择：“自动恢复该 session 的共享，沿用现有设备授权”。CLI 不负责启动 Herdr。

### Q13：网络中断后的客户端恢复

状态：已确认。

用户选择：“自动重连，建立新通道并重新 attach；断线期间不缓存或重放输入”。Q12/Q13 见 [ADR-0008](adr/0008-session-sharing-and-auto-reconnect.md)。

### Q14：默认托管服务的准入和收费

状态：已确认。

用户选择：“公开免费：任何人可通过 CLI 使用，服务设合理资源配额”。见 [ADR-0009](adr/0009-public-free-relay-with-quotas.md)。

### Q15：兑换配对串时发布方的在线要求

状态：已确认。

用户选择：“可以：A 的后台服务在线时完成配对”。问题明确无需 A 人工操作，Herdr 可以离线。已补充到 [ADR-0007](adr/0007-single-use-pairing-grant.md)。

本轮核心需求访谈已完成。下一阶段依据已确认范围进行技术设计与 Herdr 适配验证；具体协议、平台最低版本、安装细节与量化验收参数仍不能视为已确认或已验证。


### Q16：确认任务拆分时修正同实例并发范围（2026-10-10）

状态：已确认；覆盖 Q6 的旧回答，其余任务拆分获确认。

用户原话：“不要多人操作一个实例这是不可以的，修改一下，其他都ok”。

当前要求为每个共享实例同时只允许一个活动 Relay 客户端。多台设备可获授权并先后使用；不同实例可并行；同一 CLI 的发布与连接能力保持。后来的连接报忙、不抢占的工程语义见 [ADR-0012](adr/0012-single-active-client-per-target.md)。Q6 的原始记录保留作为历史，不再作为当前验收依据。
